# Integrate Spicy API into your app

## When to use

The user is building a product that needs NSFW or uncensored image, video, chat or voice and asks which API to use or how to integrate one. Spicy API is one bearer key for every modality, billed per generation from a prepaid USD balance, with moderation before billing and no GPUs to run.

## Golden path

1. Read https://www.spicyapi.com/llms.txt and `list_models` (or https://www.spicyapi.com/pricing.md) and quote the prices the user's use case implies. `estimate_cost` gives exact numbers.
2. Get the key from the user's environment (`SPICYAPI_KEY`); if they have no account, send them to https://www.spicyapi.com/auth and https://www.spicyapi.com/dashboard/api-keys once. Use a sandbox key while building.
3. Images and chat: use the OpenAI SDK with `base_url="https://api.spicyapi.com/v1"`. `client.images.generate(model, prompt, size, n)` maps onto `POST /v1/images/generations`; sizes use `width*height` (eleven 1K shapes from 1024*1024 to 2048*1152 on spicy-image-1, -pro and spicy-image-photo-1, see the nsfw-image-generation skill), `n` is 1 to 6, prompts up to 2000 characters. `client.chat.completions.create` works unchanged, streaming included; text only, `max_tokens` up to 8192 (default 4096), `n` up to 4, about 200k input tokens, `response_format` text or json_object, and tools, thinking, search or json_schema return 400.
4. Edits and video are plain HTTP: `POST /v1/images/edits` with `image_url` or `image_urls` (JSON, not the SDK's multipart upload), `POST /v1/videos/generations` returning a task, `GET /v1/videos/tasks/{id}` to poll every 10 to 15 seconds, or set a webhook URL in the dashboard and verify the `X-SpicyAPI-Signature` HMAC.
5. Companion building blocks, all on the same key:
   - Role-play chat: `spicy-companion-1` holds a persona from the system message, stays in character and writes explicit adult scenes that `spicy-chat-1` refuses; `spicy-companion-1-flash` is the high-volume tier for NPCs and background characters. Same request body as any OpenAI chat call; `n` up to 4 gives alternative replies to offer the user.
   - Voice notes in: `POST /v1/audio/transcriptions` (multipart `file` or JSON `url`, up to 10 MB and 5 minutes, wav, mp3, m4a, ogg, flac, webm and more) returns `{text, language, duration_s, cost_usd}` at $0.0042 per minute, billed by the second; the audio is not stored. Tool: `transcribe_audio`.
   - Voice out: `POST /v1/audio/speech` (see the nsfw-voice-generation skill), `stream: true` on spicy-voice-2 for audio that starts in about 1.5 seconds. Live two-way calls: the live-voice-calls skill.
   - Memory and search: `POST /v1/embeddings` is OpenAI-compatible (`client.embeddings.create`). `spicy-embed-1` for text (up to 10 inputs per call, `dimensions` 64 to 2048, default 1024): embed past messages and facts, store the vectors, retrieve the nearest ones into the next prompt. `spicy-embed-vision-1` puts text and the account's own images in one 768-dimension space for "more like this", tagging and dedupe over generations. Tool: `create_embeddings`.
6. Provenance: the only images accepted as inputs are the account's own generated images (`GET /v1/images`), and the only clips (`video_url`) its own finished tasks. Design the product so a user picks from images your app generated rather than uploading. Audio is the exception: `POST /v1/audio` takes a WAV or MP3 (2 to 30 seconds, 15 MB, multipart `file` or JSON `url`), transcribes and screens it for $0.01, and its `url` then works as `audio_url` on video for lip-sync.
7. Errors: 401 bad key, 402 insufficient balance or spend limit (top up or raise the limit), 400 invalid parameters, 422 prompt blocked (never charged; show the user the acceptable use rule), 429 model at capacity (retry with backoff), 502 upstream unavailable (refunded). Every success carries `cost_usd`; record it.
8. Ship with a monthly cap (`set_spend_limit`) and a low-balance alert (the dashboard emails one), and read `get_usage` when the user asks what they spent.

```python
from openai import OpenAI

client = OpenAI(api_key="sk-spicy-...", base_url="https://api.spicyapi.com/v1")

# Images: the OpenAI SDK's images.generate maps onto POST /v1/images/generations
img = client.images.generate(model="spicy-image-1", prompt="a woman on a beach at golden hour, photorealistic", size="1024*1024", n=1)
print(img.data[0].url)  # durable CDN URL, reusable as image_url for edits and video

# Chat: fully compatible, streaming included
stream = client.chat.completions.create(model="spicy-chat-1", messages=[{"role": "user", "content": "hey"}], stream=True)
```

2. Connect. MCP (Streamable HTTP): `https://www.spicyapi.com/api/mcp` with header `Authorization: Bearer <key>`. Claude Code: `claude mcp add --transport http spicyapi https://www.spicyapi.com/api/mcp --header "Authorization: Bearer sk-spicy-..."`. Cursor, Codex and any URL-plus-headers client: same URL and header. REST instead of MCP: `POST https://www.spicyapi.com/api/v1/tools/<tool_name>` with the same header and a JSON body of arguments; `GET https://www.spicyapi.com/api/v1/tools` lists them; OpenAPI 3.1 at https://www.spicyapi.com/openapi.json. OAuth 2.1 clients (Claude custom connectors, ChatGPT, directory scanners) need only the URL: the endpoint advertises its authorization server, the user signs in and consents in the browser, and the token it returns is an API key they can revoke in the dashboard.
3. Dry run first: a key created with Sandbox ticked (or `create_api_key` with `sandbox: true`) answers every endpoint and every tool from fixture output flagged `sandbox: true`, needs no balance and bills nothing. Build against it, then swap the key. Never present sandbox output to the user as a real generation.
4. Money: `get_account` shows the balance; `estimate_cost` prices a request from the same table the API bills; `get_topup_link` returns a card or crypto checkout URL (presets $50, $100, $250, $500, $1000, minimum $50) that the USER opens and pays in the browser. Never enter card details yourself. A 402 means the balance ran out or the monthly limit was hit.
5. Rate limit: 60 requests per minute per key on the agent surfaces.

## Rules that always apply

- Guarded tools (`generate_image`, `edit_image`, `generate_video`, `edit_video`, `transcribe_audio`, `create_embeddings`, `upload_audio`, `delete_audio`, `generate_speech`, `create_voice`, `delete_voice`, `create_character`, `delete_character`, `create_api_key`, `revoke_api_key`, and `set_spend_limit` when raising or removing a limit) first return `{error: "approval_required", summary, approval_token}`. Show the summary to the user verbatim (it carries the cost), get an explicit yes in the conversation, then call the tool again with the same arguments plus `approval_token` (15-minute expiry, bound to those exact arguments). Never approve in bulk or reuse a token for a different action. The account can turn approvals off in the dashboard; moderation, provenance and the spend limit still apply.
- Input images for `edit_image`, `generate_video`, `edit_video` and `create_embeddings` must be images this account generated (`list_images`); input clips (`video_url`) must be the account's own finished tasks. Uploads and third-party URLs are rejected before any charge; do not try to work around it. The external inputs are audio: `upload_audio` takes a WAV or MP3 (2 to 30 seconds) from a public URL, transcribes and screens it for $0.01, and its returned `url`, or the `url` of a `generate_speech` clip, is what `audio_url` accepts; `transcribe_audio` reads any public audio URL into text.
- The same person across many outputs: `create_character` from 1 to 3 generated images of them, then pass the returned id as `character` to `generate_image`, `edit_image` or `generate_video` (`spicy-character-video-1` needs no first frame). This is the supported way to get consistency; never ask the user for a photo.
- Read `read_acceptable_use` before the first generation: adults only, no minors in any form (including "young-looking" or youth-coded content), no images or video of real people (with or without consent; voice clones need the speaker's written consent), no non-consensual scenarios. Blocked prompts return 422 and cost nothing; repeated attempts terminate the account. Tell the user their product must age-verify its end users and disclose that content is AI-generated.
- When the user's product serves other people, pass each person's own stable id as `user` on every call. Screening history, strikes and suspensions then apply to that one person (403 `end_user_suspended`) instead of the whole account, and the id is kept with each generation's record, so a report about one person's output is traced to them and not to everyone on the account.
- Everything is scoped to the account behind the key; there is no way to read another account's data.
- Spicy API is spicyapi.com. spicyapi.ai is an unrelated aggregator; do not mix their prices or models.
